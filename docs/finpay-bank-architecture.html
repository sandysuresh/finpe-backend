Bank integration Approved transaction sent to mapped bank API; response/webhook/status handled by FinPay. Admin stores encrypted bank credentials and assigns the bank to vendors. Secure connectivity; request/response validation
Nepal payout Bank / payout partner completes beneficiary-side NPR payout after India-side settlement. Partner controls; status confirmation
Reconciliation Match FinPay transactions with bank/settlement records and resolve exceptions. Reference matching; audit logs
Reports & monitoring Vendor reports, transaction reports, settlement reports, operational alerts and audit activity. Access control; monitoring; event history

Security control framework

Security areaControl / design principle
Transport securityHTTPS/TLS for vendor API, bank outbound calls and webhooks. HSTS when the application is served over TLS.
AuthenticationPortal session login (regenerate on login). API: HMAC-SHA256 over timestamp, nonce, method, path and body hash. Secret is never transmitted in the request.
AuthorizationAdmin module permissions; vendor-scoped data; encrypted IDs in URLs.
API protectionRequest validation, mandatory IP allowlist, rate limiting, generic auth errors, body-size cap, redacted API logs.
Transaction integrityUnique transaction/reference identifiers, wallet lock, status lifecycle, pending / success / failed handling.
Data protectionPassword hashing; least-privilege access; encrypted bank secrets; account numbers redacted in logs.
Outbound safetyBank and webhook URLs restricted (HTTPS in production; no private/metadata hosts; no open redirects).
Audit & monitoringAdministrative, API and transaction events retained for investigation and reconciliation.
Operational resiliencePending states, failure handling, polling/webhook and reconciliation for external bank responses.

Important: Controls describe the implemented architecture. Regulatory compliance, certification, VAPT and bank-specific production requirements should be validated before go-live.
